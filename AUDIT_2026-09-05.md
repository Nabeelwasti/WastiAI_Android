## Critical findings

### 1. Local GGUF inference was not neural inference
`WastiLocalModelRuntime` contained deterministic pseudo-logit generation, sampling, and hard-coded response text. GGUF parsing and tokenization are not equivalent to running model weights.

**Fix applied:** removed pseudo-inference and introduced a fail-closed native inference boundary. The provider is unavailable until a real native backend (for example a llama.cpp/ggml Android build) is linked and loadable.

### 2. Model integrity verification was bypassable
`WastiModelDownloader` calculated a SHA-256 value but accepted a template prefix and installed the file regardless of the verification result.

**Fix applied:** downloads now require a trusted 64-character SHA-256, reject mismatches, and only install after verification succeeds.

### 3. Model manifests contained unverified synthetic hashes
The three GGUF manifests used values that were not independently established as the upstream artifact hashes.

**Fix applied:** unverified hashes were removed. Models remain declared but are not downloadable/executable until real upstream checksums are supplied.

### 4. Release signing could silently fall back to an unsigned release
The Gradle build only attached the release signing config when a keystore happened to exist, allowing release assembly without a production signature.

**Fix applied:** release assembly now fails closed unless the keystore and signing environment are present.

### 5. Release lint was disabled
The latest push changed `abortOnError` and `checkReleaseBuilds` to false.

**Fix applied:** strict linting is restored for release builds.

### 6. CI published a debug APK as the latest release
The workflow built and published `app-debug.apk` under a fixed `v1.0.0` release.

**Fix applied:** production artifacts are signed release APKs; debug artifacts are limited to PR validation. GitHub Releases are created only from version tags.

### 7. CI had redundant fail-open license handling
The first remediation attempt added a shell-level `yes | sdkmanager --licenses` check. CI proved that this itself was incorrect under `pipefail`: `yes` exited with SIGPIPE after `sdkmanager` had already accepted the licenses.

**Fix applied:** removed the redundant shell pipeline and rely on `android-actions/setup-android`'s explicit `accept-android-sdk-licenses: true` behavior.

### 8. CI permissions were broader than necessary
The build job requested `contents: write` even though normal builds do not need repository write access.

**Fix applied:** build job uses `contents: read`.

### 9. Android WorkManager initialization was explicitly removed
The manifest removed the default WorkManager initializer while the app still depends on WorkManager scheduling.

**Fix applied:** removed the manifest override so the normal WorkManager initialization path remains intact.

### 10. Backup rules targeted the wrong Room database filename
The repository's Room database is `wasti_os_database`, while older rules targeted a different name.

**Fix applied:** backup configuration now excludes the application database domain and model artifacts, preventing sensitive database/model state from being exported by the configured backup mechanisms.

### 11. Boot receiver started a foreground service directly
The boot receiver launched the Wasti foreground daemon directly from `BOOT_COMPLETED`, while modern Android versions impose background-start and foreground-service restrictions.

**Fix applied:** boot now schedules durable WorkManager recovery and performs reconciliation under `goAsync()` instead of blindly starting the foreground service.

### 12. Credential storage was rechecked against the latest `main`
The earlier audit assumption that `CredentialRegistry.saveCredential()` still wrote plaintext secrets to Room is no longer true on the audited commit. Current `saveCredential()` stores values in encrypted preferences and purges legacy Room/shared-preference copies; `refreshAll()` only performs one-time legacy migration and immediately deletes the legacy Room values.

**Conclusion:** this specific P0 finding is considered fixed in the audited `main` state, subject to APK/runtime verification.

## Important remaining production blockers

These were deliberately not papered over with fake implementations:

- The native GGUF inference library is still not linked in the repository. A real llama.cpp/ggml Android build must be integrated and device-tested.
- Backend sensitive endpoints require production authentication/authorization rather than relying on CORS or obscurity.
- Verification must remain based on independent structured evidence; caller-supplied confidence must never promote an execution to trusted capability status.
- Production readiness must not infer live verification from startup state or generic credential counts.
- Real Android emulator/device E2E tests are required; host/Robolectric tests cannot prove physical-device execution.
- Release APK/AAB must be scanned after signing, and R8/minification behavior must be validated on a real release install.
- Foreground-service behavior still requires real Android 14+ device validation for every declared service type and start path.
- Real semantic embeddings are still required; deterministic/hash embeddings must not be represented as neural semantic embeddings.

## Engineering rule

No feature is marked operational merely because code exists, a model is listed, an API key is configured, or a test/mocked provider returns success. Wasti must distinguish declared, configured, authenticated, executable, started, completed, observed, verified, trusted, and learned states.

This audit intentionally preserves existing architecture and functionality. Fixes consolidate truth and safety rather than deleting useful systems.
